# 작업 지시서: 데이터 분석 보고서 작성 (범용)

## 1. 개요
본 작업은 제공된 데이터셋을 분석하여, 독자의 의사결정을 지원하는 **상용 리서치 데스크 수준의 분석 보고서**를 작성하는 것을 목적으로 합니다. 보고서는 dataset·upstream 칠판의 **실제 산출값**만 근거로 하며, 도메인에 맞는 용어와 지표를 사용합니다.

빈약하면 안 되는 것: **모집단 없는 총평, 축을 모르는 차트, 상위 5개만 그린 기본 막대, 「분석 결과입니다」 한 줄.**
품질 기준은 [[report/insight_craft]] — 특정 화면·차트 타입을 복제하지 말 것.

## 2. 보고서 구성 (Outline)

`analytical-standard` 패턴을 따릅니다. 블록을 줄여 표+차트만 남기지 말 것.

### 표지
- **report title**: 짧은 명사구 (query·plan title)
- **리드(executive_summary)**: 모집단 + 핵심 발견 1~3문장 (고유명 + 숫자 + 방향). 한국어 독자면 한국어 제목

### 본문
- **metrics_table + table_insight**: 핵심 지표 표와 해석. 표 `header` 한글
- **primary_chart + chart_insight**: 질문에 맞는 차트(비교/추세/구성/관계). 해석은 항목 **이름**
- **appendix_table** *(선택)*

지표를 오해할 수 있으면 요약 직후 정의 한 줄. 모든 보고서에 고정 방법론 섹션을 넣지 말 것.

### 마무리
- **conclusions**: 근거 요약, 한계, 후속 관찰

## 3. 작성 가이드라인

### 데이터 및 내용 원칙
- **정확성**: 본문 수치는 upstream payload·chart data 와 일치. 추측·미확인 값 금지.
- **빈 데이터**: parquet/집계가 0행이면 데모 표·예시 수치를 만들지 말 것. 「데이터 없음」을 명시.
- **파생 지표**: 원본 합만 나열하지 말 것. 질문에 필요한 순위·기준선·극단값을 analyze 가 먼저 계산.
- **도메인 적합성**: query·plan·dataset 에 맞는 용어.
- 첫 문장에 **고유명 + 숫자**. 주어 없는 총평 금지.

### 시각화
- 차트 종류는 질문·데이터 특성에 맞게 (visual_design 표). 가로 그룹 bar·0선은 **양·음 상대 비교일 때** 적합하다. 시계열·산점도 질문에 강제하지 말 것.
- ranking 을 비교 목적과 무관하게 5개로 자르지 말 것. 없는 그룹을 채워 넣지 말 것.
- 톤·섹션 강조는 visual_design. 핵심 발견 1곳만 highlight.

## 4. 품질 점검
- [ ] 리드에 모집단과 고유 사실이 있다
- [ ] chart_insight / table_insight 가 구체 항목명과 숫자를 말한다
- [ ] 차트 타입이 질문에 맞다
- [ ] 표·차트 수치가 upstream 과 일치
- [ ] 데모 행·예시 수치 없음
- [ ] layout required_roles 충족
