# 상용 분석 보고서 — 품질 기준

**상용(commercial)** 은 특정 화면·차트·색을 복제하는 것이 아니다.
구독형 리서치·IB 데스크처럼 **한 장에서 의사결정이 되게** 쓰는 것이다.

빈약하면 안 되는 것: 모집단 없는 총평, 정의 없는 축, 상위 5개만 그린 기본 세로 막대, 「분석 결과입니다」 한 줄.
수치는 칠판·parquet **실값만**. 비면 「데이터 없음」. 데모 행·예시 업종·만 단위로 떨어지는 가짜 숫자 금지.

특정 첨부본의 지표명(Flow RS 등)·25개 업종·관련 분석 3카드·영문 Executive Summary 를 **모든 보고서에 강제하지 말 것.** 질문은 query·데이터가 정한다.

## 한 장에 있어야 하는 것

1. **제목** — 무엇을 봤는지 짧은 명사구
2. **요약** — 모집단(몇 건·몇 그룹·기간) + 핵심 발견. **고유명 + 숫자 + 방향**이 첫 문장에 있어야 한다. 주어 없는 「증가 추세입니다」 금지
3. **근거** — 표와 차트. 차트 **종류는 질문에 맞게** (비교 / 추세 / 구성 / 관계). visual_design 표 참고
4. **해석** — 표·차트 **직후**. 항목을 이름으로 말한다. 「데이터가 보여줍니다」 금지
5. **결론** — 후속 관찰·한계 한 줄. 표·차트로 끝내지 말 것

지표가 합계인지 평균 대비 상대값인지, 독자가 축을 오해할 수 있으면 **한 줄로 정의**한다. 모든 보고서에 방법론 섹션을 복제하라는 뜻이 아니다.

## analyze (서사·차트의 원천)

원본 컬럼 합만 넘기면 보고서가 빈약해진다. **질문에 필요한 파생**을 칠판에 둔다.

질문에 맞게 고른다 (전부 필수 키가 아님):

| 성격 | 예 |
|------|----|
| 모집단 | 행 수, 그룹 수, 기간 |
| 기준선 | 전체 평균, 전일, 벤치마크 — 비교의 0점 |
| 순위 | 그룹명 + 핵심 지표. **있는 그룹을 숨기지 말 것** (10개면 10개. 25개를 만들어 내지 말 것) |
| 극단 | 상위·하위 이름과 수치 |
| 괴리 | 두 지표가 엇갈리는 항목 (있을 때만) |

상대 비교가 질문이면 `group_mean - universe_mean` 같은 파생을 계산한다. 시계열·비중·밸류 질문이면 그 질문에 맞는 집계를 한다.

## visual

차트는 보고서의 얼굴이다. 기본 파랑 막대·무지개 파이·「분석 차트」 제목은 쓰지 않는다.

- **질문에 맞는 타입** — 카테고리 비교는 가로 bar 가 읽히기 쉽고, 양·음 상대값이면 0선이 도움이 된다. 시계열은 line. 구성(조각 적음)은 도넛. 관계는 scatter.
- 제목은 메시지형 한글. 카드가 제목을 그리므로 Option `title.show=False` — 차트 안에 같은 제목을 다시 그리지 말 것
- 단위는 `title.subtext` 가 아니라 **value 축 `name`** (`만 주`, `억 원`). 범례와 겹친다
- 범례는 `bottom` 만. **`legend.top` 금지**
- 축 숫자 `-4,000,000` 금지. series 를 만/억으로 나누고 `hideOverlap`, `splitNumber` 4~5
- `grid` 는 **단일 object**. `containLabel=True` 이면 left/top 을 크게 두지 말 것 (플롯이 한쪽으로 밀림)
- 비교가 목적인데 상위 5개만 자르지 말 것. 길면 appendix 로 나눈다

## narrative

표+차트만 붙이고 끝내지 말 것. 요약·해석·결론이 본문이다.
한국어 독자면 **한국어 제목**. 영문 섹션명(Executive Summary)을 강제하지 말 것.
볼드는 카드당 핵심 1~2곳.

## release

초안의 한글을 **다시 쓰지 말 것.** junk·placeholder·수치 불일치·누락 블록만 patch 하고 출판한다.
한글을 유니코드 공백으로 치환하면 화면이 비어 보인다.
